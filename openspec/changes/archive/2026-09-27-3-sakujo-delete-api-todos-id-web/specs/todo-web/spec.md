## ADDED Requirements

### Requirement: 行の削除
行の「削除」ボタンを押すと、web は確認のダイアログを出さずに、その行の todo の `id` で `DELETE /api/todos/:id` を送らなければならない(SHALL)。成功したら(status 204)その行を一覧から取り除き、他の行とその順は変えてはならない(MUST NOT)。取り除いて行が 0 になったら、T1a のとおり行の並びの代わりに文「まだ todo がありません」を描かなければならない(SHALL)。API が status 404 を返したときは、その todo が既に無いものとして成功と同じく行を取り除かなければならない(SHALL)。API の応答を待つ間、その行は押す前のまま残し(SHALL)、同じ行の「削除」ボタンをもう一度押しても API に送ってはならない(MUST NOT)。API が 404 以外の失敗を返したとき、または要求そのものが失敗したときは、行を押す前のまま残し、その行の「削除」ボタンを再び押せる(押せば再び API に送る)状態に戻さなければならない(SHALL)。

#### Scenario: 削除ボタンでの行の削除
- **WHEN** 「牛乳を買う」「掃除する」「本を返す」の 3 行が描かれた画面で「掃除する」の行の「削除」ボタンを押す
- **THEN** 確認のダイアログは出ず、`DELETE /api/todos/:id` に「掃除する」の `id` が送られ、応答の後の一覧は「牛乳を買う」「本を返す」の 2 行がこの順に残る

#### Scenario: 完了の行の削除
- **WHEN** 完了の「牛乳を買う」と未完了の「掃除する」の 2 行が描かれた画面で「牛乳を買う」の「削除」ボタンを押す
- **THEN** `DELETE /api/todos/:id` に「牛乳を買う」の `id` が送られ、応答の後は未完了の「掃除する」の 1 行だけが残る

#### Scenario: 最後の 1 件の削除
- **WHEN** 1 行だけが描かれた画面でその行の「削除」ボタンを押す
- **THEN** 応答の後、todo の行は 1 つも無く、文「まだ todo がありません」が描かれる(T1a)

#### Scenario: 0 件にした後の追加
- **WHEN** 最後の 1 件を消して T1a になった画面で、入力欄に「掃除する」を入れて「追加」を押す
- **THEN** 文「まだ todo がありません」が消えて、「掃除する」の行が 1 行描かれる

#### Scenario: 削除の応答待ちの間の再押下
- **WHEN** 行の「削除」ボタンを押し、API の応答が返る前にもう一度押す
- **THEN** API に送られるのは 1 回だけで、応答が返るまで行は残り、応答の後に行が消える

#### Scenario: 既に無い todo の削除
- **WHEN** 行の「削除」ボタンを押し、API が status 404 を返す
- **THEN** その行は一覧から消える

#### Scenario: 削除の失敗
- **WHEN** 行の「削除」ボタンを押し、API が status 500 を返す
- **THEN** その行は押す前のまま残り、その後もう一度押すと再び `DELETE /api/todos/:id` が送られる

#### Scenario: 削除の要求の失敗
- **WHEN** 行の「削除」ボタンを押し、要求そのものが失敗する(応答が返らない)
- **THEN** その行は押す前のまま残り、その後もう一度押すと再び `DELETE /api/todos/:id` が送られる

## REMOVED Requirements
