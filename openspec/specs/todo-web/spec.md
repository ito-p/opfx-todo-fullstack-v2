# todo-web Specification

## Purpose
todo の一覧画面。起動時に API から一覧を読んで Figma の T1(一覧)・T1a(0 件)のとおりに描き、題名を入れて追加する操作を API へつなぐ。

## Requirements

### Requirement: 起動時の一覧の表示
web は起動時に `GET /api/todos` から一覧を読み、1 件以上あれば T1 のとおり、見出し「todo」・追加の form・todo の行の並びを描かなければならない(SHALL)。行は API が返した順に並べ、各行は左からチェックボックス・題名・「削除」ボタンを持たなければならない(SHALL)。`done` が `false` の行のチェックボックスは印の無い状態で描く(SHALL)。

#### Scenario: 起動時の一覧の行
- **WHEN** API が「牛乳を買う」「掃除する」「本を返す」の 3 件(どれも `done` が `false`)を返す状態で web を起動する
- **THEN** 画面には見出し「todo」、プレースホルダー「題名を入力」の入力欄、「追加」ボタン、その 3 件の行がこの順に描かれ、各行にチェックボックス(印なし)・題名・「削除」ボタンがある

### Requirement: 0 件の表示
一覧が 0 件のとき、web は T1a のとおり、行の並びの代わりに文「まだ todo がありません」を描かなければならない(SHALL)。

#### Scenario: 0 件の画面
- **WHEN** API が空の配列を返す状態で web を起動する
- **THEN** 画面には見出し「todo」・追加の form・文「まだ todo がありません」が描かれ、todo の行は 1 つも無い

### Requirement: 題名の追加
入力欄に題名を入れて「追加」ボタンを押すか Enter を押すと、web は入力をそのまま題名として `POST /api/todos` に送らなければならない(SHALL)。成功したら返った todo の行を一覧の末尾に加え、入力欄を空にしなければならない(SHALL)。0 件の文が出ていれば、それを行の並びに置き換えなければならない(SHALL)。入力が空、または空白だけのときは API に送ってはならず(MUST NOT)、画面は変えない(SHALL)。API が失敗を返したときは行を加えず、入力欄の内容を残さなければならない(SHALL)。

#### Scenario: 追加した題名の行
- **WHEN** 1 件の一覧が描かれた画面で入力欄に「掃除する」を入れて「追加」を押す
- **THEN** `POST /api/todos` に題名「掃除する」が送られ、応答の todo の行が一覧の末尾に加わり、入力欄は空になる

#### Scenario: 0 件からの追加
- **WHEN** 0 件の画面で入力欄に「牛乳を買う」を入れて Enter を押す
- **THEN** `POST /api/todos` に題名「牛乳を買う」が送られ、文「まだ todo がありません」が消えて、その todo の行が 1 行描かれる

#### Scenario: 空白だけの入力の不送信
- **WHEN** 入力欄が空、または空白だけの状態で「追加」を押す
- **THEN** `POST /api/todos` は呼ばれず、一覧も入力欄も変わらない

#### Scenario: 追加の失敗
- **WHEN** 入力欄に「掃除する」を入れて「追加」を押し、API が status 400 を返す
- **THEN** 一覧に行は加わらず、入力欄には「掃除する」が残る

### Requirement: まだ動かないチェックボックスと削除ボタン
各行のチェックボックスと「削除」ボタンは押せる形で描くが、押しても画面の状態を変えてはならず(MUST NOT)、API を呼んではならない(MUST NOT)。

#### Scenario: チェックボックスと削除ボタンの無反応
- **WHEN** 行のチェックボックスと「削除」ボタンを押す
- **THEN** チェックボックスは印の無いまま、行は残ったままで、API は呼ばれない
