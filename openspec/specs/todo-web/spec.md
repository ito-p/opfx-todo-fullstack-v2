# todo-web Specification

## Purpose
todo の一覧画面。起動時に API から一覧を読んで Figma の T1(一覧)・T1a(0 件)・T1b(完了あり)のとおりに描き、題名を入れて追加する操作とチェックボックスで完了を切り替える操作を API へつなぐ。

## Requirements

### Requirement: 起動時の一覧の表示
web は起動時に `GET /api/todos` から一覧を読み、1 件以上あれば T1 のとおり、見出し「todo」・追加の form・todo の行の並びを描かなければならない(SHALL)。行は API が返した順に並べ、各行は左からチェックボックス・題名・「削除」ボタンを持たなければならない(SHALL)。`done` が `false` の行のチェックボックスは印の無い状態で描く(SHALL)。`done` が `true` の行は T1b のとおり、チェックボックスを印の付いた状態で、題名を取り消し線付きの灰色で描かなければならない(SHALL)。

#### Scenario: 起動時の一覧の行
- **WHEN** API が「牛乳を買う」「掃除する」「本を返す」の 3 件(どれも `done` が `false`)を返す状態で web を起動する
- **THEN** 画面には見出し「todo」、プレースホルダー「題名を入力」の入力欄、「追加」ボタン、その 3 件の行がこの順に描かれ、各行にチェックボックス(印なし)・題名・「削除」ボタンがある

#### Scenario: 起動時の完了の行
- **WHEN** API が「牛乳を買う」(`done` が `true`)「掃除する」「本を返す」(どちらも `done` が `false`)を返す状態で web を起動する
- **THEN** 「牛乳を買う」の行はチェックボックスに印が付き、題名が完了の見た目(取り消し線・灰色)で描かれ、ほかの 2 行は印なし・通常の題名で描かれる

### Requirement: 0 件の表示
一覧が 0 件のとき、web は T1a のとおり、行の並びの代わりに文「まだ todo がありません」を描かなければならない(SHALL)。

#### Scenario: 0 件の画面
- **WHEN** API が空の配列を返す状態で web を起動する
- **THEN** 画面には見出し「todo」・追加の form・文「まだ todo がありません」が描かれ、todo の行は 1 つも無い

### Requirement: 題名の追加
入力欄に題名を入れて「追加」ボタンを押すか Enter を押すと、web は入力をそのまま題名として `POST /api/todos` に送らなければならない(SHALL)。成功したら返った todo の行を一覧の末尾に加え、入力欄を空にしなければならない(SHALL)。0 件の文が出ていれば、それを行の並びに置き換えなければならない(SHALL)。入力が空、または空白だけのときは API に送ってはならず(MUST NOT)、画面は変えない(SHALL)。API が失敗を返したときは行を加えず、入力欄の内容を残さなければならない(SHALL)。

#### Scenario: 追加した題名の行
- **WHEN** 1 件の一覧が描かれた画面で入力欄に「掃除する」を入れて「追加」を押す
- **THEN** `POST /api/todos` に題名「掃除する」が送られ、応答の todo の行が一覧の末尾に加わり、入力欄は空になる

#### Scenario: 0 件からの追加
- **WHEN** 0 件の画面で入力欄に「牛乳を買う」を入れて Enter を押す
- **THEN** `POST /api/todos` に題名「牛乳を買う」が送られ、文「まだ todo がありません」が消えて、その todo の行が 1 行描かれる

#### Scenario: 空白だけの入力の不送信
- **WHEN** 入力欄が空、または空白だけの状態で「追加」を押す
- **THEN** `POST /api/todos` は呼ばれず、一覧も入力欄も変わらない

#### Scenario: 追加の失敗
- **WHEN** 入力欄に「掃除する」を入れて「追加」を押し、API が status 400 を返す
- **THEN** 一覧に行は加わらず、入力欄には「掃除する」が残る

### Requirement: 完了の切り替え
行のチェックボックスを押すと、web はその行の todo の `done` の反対の値を `PATCH /api/todos/:id` に送らなければならない(SHALL)。成功したら返った todo の `done` でその行を描き直さなければならない(SHALL): `true` なら T1b の完了の見た目、`false` なら T1 の未完了の見た目。行の位置と他の行は変えない(SHALL)。API の応答を待つ間、チェックボックスの見た目は押す前のまま変えず(SHALL)、同じ行のチェックボックスをもう一度押しても API に送ってはならない(MUST NOT)。API が失敗を返したとき、または要求そのものが失敗したときは、行を押す前の見た目のまま残し、その行のチェックボックスを再び押せる(押せば再び API に送る)状態に戻さなければならない(SHALL)。チェックボックスの読み上げの名前は、未完了の行では「<題名> を完了にする」、完了の行では「<題名> を未完了に戻す」でなければならない(SHALL)。

#### Scenario: 未完了の行の完了
- **WHEN** 「牛乳を買う」「掃除する」の 2 行(どちらも未完了)が描かれた画面で「牛乳を買う」のチェックボックスを押す
- **THEN** `PATCH /api/todos/:id` にその todo の `id` と `done: true` が送られ、応答の後「牛乳を買う」の行はチェックボックスに印が付き題名が完了の見た目になり、チェックボックスの読み上げの名前が「牛乳を買う を未完了に戻す」になり、行の位置は 1 行目のまま、「掃除する」の行は変わらない

#### Scenario: 完了の行の未完了
- **WHEN** 完了の「牛乳を買う」の行のチェックボックスを押す
- **THEN** `PATCH /api/todos/:id` にその todo の `id` と `done: false` が送られ、応答の後その行はチェックボックスの印が消え題名が通常の見た目に戻り、読み上げの名前が「牛乳を買う を完了にする」になる

#### Scenario: 応答待ちの間の再押下
- **WHEN** 未完了の行のチェックボックスを押し、API の応答が返る前にもう一度押す
- **THEN** API に送られるのは 1 回だけで、応答が返るまでチェックボックスは印の無いまま、応答の後に完了の見た目になる

#### Scenario: 切り替えの失敗
- **WHEN** 未完了の行のチェックボックスを押し、API が status 404 を返す
- **THEN** その行はチェックボックスの印が無く題名が通常の見た目のまま残り、その後もう一度押すと再び `PATCH /api/todos/:id` に `done: true` が送られる

#### Scenario: 切り替えの要求の失敗
- **WHEN** 完了の行のチェックボックスを押し、要求そのものが失敗する(応答が返らない)
- **THEN** その行はチェックボックスに印が付き題名が完了の見た目のまま残り、その後もう一度押すと再び `PATCH /api/todos/:id` に `done: false` が送られる

### Requirement: まだ動かない削除ボタン
各行の「削除」ボタンは押せる形で描くが、押しても画面の状態を変えてはならず(MUST NOT)、API を呼んではならない(MUST NOT)。

#### Scenario: 削除ボタンの無反応
- **WHEN** 行の「削除」ボタンを押す
- **THEN** 行は残ったままで、API は呼ばれない
